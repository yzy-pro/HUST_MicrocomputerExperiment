\subsection{实验内容}
在 Keil 环境中设计一个基于 AT89S52 单片机的智能垃圾分类处理系统，用户通过 P2 口的输入和 P1 口输出（上电复位初始状态为全 1），模拟小区垃圾回收终端系统的运行状态，系统需要实现以下功能：
\begin{itemize}
    \item 小区居民通过键入相应按键选择垃圾类型（分别用 P2.4$\sim$P2.7 端口模拟按键输入，低电平有效，P2.7=0、P2.6=0、P2.5=0、P2.4=0 分别代表“塑料纸张”、“玻璃金属”、“厨余垃圾”和“危害垃圾”四类）。
    \item P1.0$\sim$P1.3 四位代表垃圾桶盖开关控制，控制名为“塑料纸张”、“玻璃金属”、“厨余垃圾”和“危化品垃圾”四个垃圾桶盖，高电平为关闭状态，低电平为打开状态。
    \item 垃圾桶盖每次打开的时间缺省值为 8s，然后自动关闭，请采用循环程序配合 NOP 指令完成延时子程序，精度控制在 0.1s 以内。
\end{itemize}
请编写程序，实现用户键入，控制相应的垃圾桶盖打开和关闭。

\subsection{提高部分（申优选做）}
\begin{itemize}
    \item 系统初始化后，随机生成 4 个 0~9 的整数，置于寄存器 R0~R3 中表示四个垃圾桶的剩余容量。用户每次投递之后，容量相应减少。当投放垃圾超出剩余容量后，对应的标志位发生变化（自行定义），便于提醒物业及时清理，此时再次按键投放时，该桶盖不再打开避免溢出。
    \item 其他个性化设计。
\end{itemize}

\section{设计思路}
本系统基于AT89S52单片机核心架构，采用模块化程序设计思想，围绕垃圾分类投放的核心需求，拆分功能模块实现全流程控制，整体设计逻辑如下：
\begin{enumerate}
    \item \textbf{系统初始化模块}：上电后配置P1口为高电平0xFF（所有桶盖默认关闭），并清零位于20H内存上的4个垃圾桶满载标志位，将其同步至P3口状态以控制指示灯。设置定时器T0工作在模式1并启动，将其自由运行的计数值作为随机数生成的扰动源，随后调用伪随机数生成子程序，为4个垃圾桶生成0-9的初始剩余容量（储存在R0~R3寄存器中）。
    \item \textbf{按键检测与分支跳转模块}：在主循环中，直接使用JNB指令轮询扫描P2.7$\sim$P2.4口的低电平信号（输入有效）。若检测到对应按键被按下，主循环将直接跳转至相应类型垃圾的投放处理分支，否则将持续循环扫描按键。
    \item \textbf{垃圾投放与容量管理模块}：在具体的投放处理分支中，系统首先检查20H寄存器中对应的满载标志。若标志位已置1或当前容量寄存器减量前已为0，表示垃圾桶已满，系统拒绝开盖，进入按键释放等待逻辑；若未满，将对应容量减1（减至0时同步更新满载标志并点亮LED），拉低P1口对应引脚即可开启桶盖。此时系统调用延时子程序保持8秒，随后拉高P1口关闭桶盖，并强制等待按键释放（WAIT\_RELEASE）避免按键连发。
    \item \textbf{多重循环延时子程序}：12MHz标称晶振下，利用嵌套循环辅以NOP空操作来消耗指令周期：底层为一个百毫秒级的延时函数（内部进行$166 \times 200$次的DJNZ定周期减量跳转，估算时长100ms），外围固定调用该子程序80次产生误差接受范围内的8秒延迟，拼凑出盖板打开维持时间。
    \item \textbf{硬件定时随机与指示模块}：读取自由不受控的定时器内置TL0、TH0计数器的值充当随机数引子，经过多项常数XRL异或扰动、RL/RR循环移位与掩码操作后，采用循环减10的方式进行模10取余，得出0-9宽度的随机容量初值。同时采用掩码方式融合20H满载标志位写出至P3外设寄存器，实现在P3.0~P3.3端口满载时的LED发光指示预警。
\end{enumerate}

\section{实验问题分析与对策}

\begin{enumerate}
    \item \textbf{伪随机数生成的随机性问题}：
    \begin{itemize}
        \item \textbf{问题}：在单片机系统中生成真正的随机数较为困难，常规算术方法容易在每次复位后产生固定的初始序列，导致每次开机容量一致。
        \item \textbf{对策}：在课上受到启发并查阅资料后得知，可以利用系统不可预知的物理运行状态作为扰动源产生随机数。具体来说，程序初始化后开启定时器 T0 自由运行，在提取随机数时，读取处于自由变换中的 TH0 和 TL0 计数值。但是这样产生的随机数较容易预测，此时通过常数异或、循环移位）等位运算打乱数据规律，最后通过循环减10求模，成功获得了在 0~9 之间分布且难以预测的随机初始容量。但是这样产生的随机数仍然是伪随机，在实际应用中如果希望获得真随机数可以使用外部随机数发生模块获得真随机数。
    \end{itemize}
    
    \item \textbf{SJMP跳转问题}：
    \begin{itemize}
        \item \textbf{问题}：在程序设计过程中，初始版本在主程序扫描到对应按键后，直接使用SJMP指令跳转到对应的投放处理分支。由于SJMP只能跳转-128到+127字节范围内的地址，导致部分分支因距离过远无法正确跳转，按下按键后垃圾桶盖始终无法被打开。
        \item \textbf{对策}：将SJMP指令替换为LJMP指令，允许跳转到任意地址范围内的分支处理程序，成功解决了跳转异常问题，保证了程序的正确执行流程。
    \end{itemize}
    
    \item \textbf{按键自动复位问题}：
    \begin{itemize}
        \item \textbf{问题}：程序设计时，我希望设计按键按下后会自动复位为高电平，于是设计了程序
        \begin{lstlisting}[language={[x86masm]Assembler}]
        KEY_AUTO_RESET:
        ORL     P2, #0F0H
        RET
        \end{lstlisting}
        希望通过将P2口的低4位强制置1来实现按键自动复位，但在实际测试中发现，这段代码只能复位P2对应的寄存器，并不能真正改变外部硬件引脚的电平状态。
        \item \textbf{对策}：经过仔细思考，我意识到按键的电平状态是由外部硬件电路决定的，单片机内部的指令无法直接改变外部引脚的电平。在仿真中无法模拟出按键自动复位的效果，因此在仿真过程中需要手动将按键对应的P2口引脚拉高来模拟按键释放的状态。
    \end{itemize}
\end{enumerate}
